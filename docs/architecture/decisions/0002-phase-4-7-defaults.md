# 0002 — Phase 4–7 Sprint Defaults

These are working defaults for the Phase 4–7 sprint (Roadmap and Project Workspace, Document Vault, Document Intelligence, Consistency and Reuse), decided on 2026-09-12. They follow the same pattern as `0001-day-1-defaults.md`. Decision #3 and #6 are explicitly provisional — revisit #3 when there's an actual budget for paid extraction calls, and #6 once real accuracy data exists to calibrate against.

| # | Decision | Choice | Rationale | Status |
|---|---|---|---|---|
| 1 | Storage provider for Phase 5 | `local` filesystem adapter (`STORAGE_LOCAL_PATH`), behind a `StorageProvider` interface. `s3` implementation stubbed to throw `"not configured"`. All reads go through an authorized download endpoint — no static file mount, no direct fetchable URL for `storageKey`. | Real S3 is Phase 15 (Terraform/AWS) work. Building the interface now and the real adapter later is fine; a static path would bypass the object-level auth check entirely. | Final for this sprint |
| 2 | Job queue for async extraction | Postgres-backed `Job` table + a polling worker process. Not SQS/EventBridge. | Matches the blueprint's own "AWS is a later phase" sequencing; a DB-backed queue is enough to prove async + retry + idempotency. | Final for this sprint |
| 3 | Extraction provider | Build the `ExtractionProvider` interface. Implement and **use only** `MockExtractionProvider` (deterministic, fixture-keyed by file hash) this sprint. Add an `AnthropicExtractionProvider` **stub** that throws `"not enabled this sprint"` if selected — not wired to make real API calls. Only the stub file may reference the Anthropic SDK, and nothing imports it by default. `LLM_PROVIDER` defaults to `"mock"` in every local/CI environment. | No budget line for paid API calls this sprint. Every Phase 6 exit criterion (async behavior, confidence handling, unknown-stays-unknown, failure recovery) is fully provable against the mock. | **Provisional** — revisit when there's a real demo or pilot user to justify the spend |
| 4 | ApprovalInstance status states (Phase 4) | `blocked \| available \| in_progress \| done`, settable by the applicant only (officer-driven transitions are Phase 9+). Client-requested transitions: `available → in_progress` and `in_progress → done` ONLY. All other transitions rejected, specifically `blocked → in_progress`, `blocked → done`, `available → done`, `in_progress → available`, `in_progress → blocked`, and anything from `done`. `blocked → available` only happens server-side, via dependency re-evaluation — never a client-requested transition. | Keeps Phase 4 a display/manual-status layer, not a workflow engine. Allowing a client to move `blocked → in_progress` would let an API caller start work whose prerequisite isn't satisfied, defeating the dependency graph. | Final for this sprint |
| 5 | Which evaluation outcomes get an ApprovalInstance | `applicable` and `needs_information` get one. `not_evaluable` gets one too, with `attentionRequired` **derived at read time** from the linked `evaluationResult.outcome === "not_evaluable"` — never stored as a second, independently-settable field. `not_applicable` gets no instance. | Consistent with the Phase 2 bug fix: `not_evaluable` must stay visibly distinct from a confident negative all the way through the roadmap. Deriving it from the join (not duplicating it) is what guarantees it can't drift out of sync with the actual evaluation. | Final for this sprint |
| 6 | Confidence threshold for "needs review" | `EXTRACTION_REVIEW_THRESHOLD` env var, default `0.6`, applied per-field — not a hardcoded number in an `if` statement. | The blueprint specifies no number. Picking one and writing it down beats leaving the behavior ambiguous, but it must stay a config value, not code, since it's a placeholder pending real accuracy data. | **Provisional** — not a validated accuracy threshold |
| 7 | Reuse scope | Same-project reuse only this sprint. Same-applicant/premises reuse *across* projects is a real blueprint concept but is deferred — it raises a cross-project authorization question that isn't solved yet. | Narrower is safer than letting one user's document surface as a reuse candidate in another user's project before the authorization model is proven. | Final for this sprint |
| 8 | Document classification scope | Auto-classification (Phase 6) only chooses among Phase 1's existing brewery `DocumentDefinition` rows — no open-ended document taxonomy. | Matches the brewery-only scope decision already made for Phase 1; don't let Phase 6 quietly widen it. | Final for this sprint |

**No paid services are required to build or pass any Phase 4–7 exit criterion.** Postgres, Docker Compose, pnpm, the graph rendering library, and local filesystem storage are all free/self-hosted. The one deferred paid dependency is Decision #3 — flip it deliberately, later, when there's a reason to.
